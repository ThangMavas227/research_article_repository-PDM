# API contract (backend `http://localhost:8080`)

All errors have one shape: `{"error": "message"}`. JSON in, JSON out.

## Login and permissions
- `POST /api/auth/login` with `{ "username", "password" }` returns `200 { "token", "user": { "id", "username", "role" } }`.
  Wrong login: `401`. Missing field: `400`.
- Send the token on every request that needs login: header `Authorization: Bearer <token>`.
  Keep it in memory or localStorage; there is no cookie. A token lasts 8 hours and is lost if the backend restarts
  (then calls return `401` and the user logs in again).
- `GET /api/auth/me` returns `200 { id, username, role }` (`401` if not logged in). Use it to show or hide admin buttons.
- `POST /api/auth/logout` returns `204`; the token stops working.
- Roles: `reader` can only read. `admin` can also add, edit and delete articles.
  No token: `401`. Logged in as reader: `403`.
- Demo accounts: `admin` / `Admin@123`, `reader1` / `Reader@123`.

## Article object (the same everywhere)
```json
{ "id": "AR003", "title": "...", "year": 2023, "doi": "10.1007/...", "abstract": "... or null",
  "venueId": "V001", "venueName": "ACM Transactions on Database Systems", "editionNumber": 1, "startPage": 123,
  "authors":    [ { "id": "AU010", "name": "George Papadakis" } ],
  "references": [ { "id": "AR010", "title": "..." } ],
  "citedBy":    [ { "id": "AR021", "title": "..." } ] }
```
`year` comes from the edition (read-only). `authors` are in writing order.

## Endpoints
| Method and path | Who | Result |
|---|---|---|
| `GET /api/articles?keyword=&year=&page=1&size=10` | public | `200 { items: [Article], page, size, totalItems, totalPages }` |
| `POST /api/articles` | admin | `201` the new Article |
| `PUT /api/articles/{id}` | admin | `200` the updated Article |
| `DELETE /api/articles/{id}` | admin | `204` (also removes its author links, citations, subjects, keywords) |

## Body of POST and PUT
```json
{ "title": "required, max 255",
  "doi": "required, like 10.1234/abc, unique",
  "abstract": "optional (empty or null = none)",
  "startPage": 123,
  "venueId": "V001",
  "editionNumber": 1,
  "authors": [ { "id": "AU001" }, { "name": "New Author Name" } ] }
```
- **Required:** `title`, `doi`, `startPage` (>= 1), `venueId`, `editionNumber` (>= 1). The pair `venueId` + `editionNumber`
  must exist, otherwise `400`. Take both from the Article object of an existing article, or from the same edition.
- **Authors:** a list in writing order (first = position 1). Each item is **either** `{ "id": "AU001" }` (an existing author)
  **or** `{ "name": "..." }` (creates a NEW author; the same name sent twice creates two authors, so use `id` to reuse one).
  At least one author on POST. Unknown id, both id and name, or the same id twice: `400`.
- **PUT** replaces every field above. `authors` is optional: leave it out to keep the current authors,
  send a list to replace them all.
- The id of a new article (`AR026`, ...) is generated by the server; do not send it.
- No `year` in the body: it follows the edition.

## Errors
| Code | When |
|---|---|
| 400 | missing/invalid field, unknown venue/edition, unknown author, body is not JSON |
| 401 | no token, wrong or expired token, wrong password |
| 403 | logged in but not admin |
| 404 | `PUT` / `DELETE` on an id that does not exist |
| 409 | DOI already used; another article of the same edition already starts on this page |
